สวัสดีครับ เดี๋ยววันนี้นะครับ เดี๋ยวผมจะมาตอบคำถามของคุณสลิฟนะครับว่า Vanilla Rag และ Agentic Rag มันมีความแตกต่างกันยังไง และข้อดีข้อเสียของแต่ละอย่างเนี่ย มันคืออะไรนะครับ ผมอยากจะเริ่มก่อนในการเล่าว่า Vanilla Rag หรือ Rag แบบธรรมดาเนี่ย มันคืออะไร แล้วค่อยไปเล่าว่า Agentic Rag เนี่ย มันมีบทบาทอะไรก็แล้วกัน เริ่มแรกนะครับ อาจจะยกตัวอย่างคำถามว่า Is there bananas and apples นะครับ ในข้างหลังบ้านเนี่ยเราอาจจะทำการเก็บเอกสารอยู่แล้วเกี่ยวกับกล้วยแล้วก็แอปเปิ้ลนะครับ ถ้าเราจะพูดถึงตัว vanilla rag เนี่ยมันจะมีความเป็น programmatic หรือมีความเป็นตายตัวนิดหนึ่ง คือพอคนถามมาปุ๊บ curry มันก็เลยจะป้อน curry ทั้งหมดไปเลย Is there bananas and apples เข้าไป อันเนี้ยครับมันก็ถ้าทุกคนศึกษา Rag Application อะไรพวกเนี้ยมาก่อนแล้วอะ Query เช่น Is there Bananas Apple ก็จะถูกแปลงกลายเป็น Vector จากการผ่านตัว Embedding Model แล้ว Vector เนี้ยก็จะถูกการ search นะครับจากตัว Vector database เพื่อที่จะคืนคืน Top K หรือว่า Top matching search resource ออกมาให้ Large Language Model ไปตอบเรานะครับ อันเนี้ยก็คือจะเป็น Typical flow ของ programmatic หรือว่าของ vanilla drag ละกัน มันจะเป็นอย่างงี้ตลอดเลย ถึงแม้ว่าคำถามคุณจะเป็นอะไรก็ตามเนี่ย มันก็จะผ่าน flow นี้คือ query embed แล้วก็ search vector แล้วก็มี LM มาตอบ แต่พอมันกลายเป็นตัว agentic drag สมมุตินะครับเป็นคำถามเดิม is their banana and apple สิ่งที่เกิดขึ้นก็คือแทนที่มันจะไปวิ่งเข้าหาตัว embedding model ก่อนอย่างแรกนะครับ มันก็จะไปถาม LM ตัวใหญ่ก่อนว่า LM คุณคิดหน่อยว่าถ้าคำถามอะมันมาอย่างงี้ is that banana and apple เนี่ยเราควรที่จะโยนคำถามหรือ query อะไรเข้าไปในอะไรที่เรียกว่า search tool นะครับ search tool แปลว่าเราแค่เอากล่องเส้นปะสีม่วงเนี่ยมานะครับ เราก็เขียนเป็นฟังก์ชันอันเนี้ยก็คือจะเรียกว่า search tool tool เนี้ยจะมีหน้าที่แปลงจาก query นะครับให้กลายเป็นเวกเตอร์เราเอาไป search จากเวกเตอร์แล้วก็คืน top K resource มาเนี้ย LM ก็จะคิดเองว่าเราควรที่จะป้อน query อะไรเข้าไปใน search tool นะครับ หลังจากที่ query เนี่ยถูกป้อนออกมาแล้ว แล้วก็มี Top K Resort LM ก็จะคิดเพิ่มเติมว่าฉันมี information พอหรือยังในการตอบของคนที่ถามได้ นอกจากตอนเนี้ยมันอาจจะคิดไปว่าอยากจะได้เอาแค่บรรดาหน้า แต่ว่ามันมันมีข้อมูลไม่พอ มันก็เลยคิดเพิ่มว่าเฮ้ย งั้นเราต้องยิงเข้า tool นี้ search tool เนี้ยเพิ่มยิงเขา Apple เพิ่มไปให้มันไป search เข้ามานะครับ มันก็จะวิ่งเข้าไปเสิร์ชรอบที่สอง แล้วก็จะคืนมาว่าโอเคฉันรู้แล้วว่าคำตอบเนี่ยมันคืออะไร จะเห็นได้ว่าพอเป็น Asiatic Rag เนี่ยมันก็จะมีการยิงตัวทรูเรื่อยเรื่อยเรื่อยเรื่อยเรื่อย จนกว่ามันจะมีได้คำตอบ บางครั้งมันอาจจะเรียกทรูแค่ทีเดียวนะ ในภาพเนี้ยผมโชว์ว่ามันเรียกทรูสองที แต่มันจะเรียกมากกว่านั้นก็ได้สามสี่ทีห้าทีจนกว่าจะได้คำตอบ เพราะฉะนั้นก็เลยจะมาสู่ข้อดีข้อเสียแล้วกันนะครับ ของ Agentic Rag เทียบกับ Rag ธรรมดา ข้อดีของมันเนี่ยคือมันอาจจะ resource in คำตอบที่ดีขึ้น เนื่องจากว่า search resource ของมันเนี่ยน่าจะมี น่าจะดียิ่งขึ้น เนื่องจากมัน search ได้หลายรอบแล้วก็ search แบบมีการคิดด้วยว่าจะ search คำว่าอะไร ในในอนาคตอะครับ ถ้าสมมุติว่าเรามี tools มากมาย ไม่ใช่แค่เราอยากจะ search อย่างเดียว แต่เราอยากจะให้มันไป take action อย่างอื่นด้วยเนี่ย การที่เราจะให้ System มันเป็น Agentic เนี่ยมันก็จะเป็นพื้นฐานที่ดีละกัน แต่ก็จะมีข้อเสียอีกมากมายนะครับ ยกตัวอย่างเช่นมีโอกาสช้าลงเพราะว่ามันมี Step เพิ่มขึ้นมาว่าให้ Large Language Model เนี่ยมีการคิดคิดนะครับ แล้วก็ Accuracy เนี่ยมันก็จะ Rely on ว่า Base Model ของเราเนี่ยมันมีความแม่นยำแค่ไหน ยกตัวอย่างเช่น Model ที่มัน Parameter น้อยน้อยหน่อยก็อาจจะทำ Agentic Lag ไม่ค่อยดีเท่าไหร่นะครับ แล้วอันเนี้ยมันก็จะกิน Token เยอะขึ้นนะครับ ทำให้ มัน expensive ขึ้นในมุม LM แล้วเราก็คาดเดามันได้ยากครับว่ามันจะทำอะไร ยกตัวอย่างเช่น Vanilla Rag เนี่ยมันตายตัวมากว่ามันจะทำอะไรเนาะ แต่พอเป็น Agentic Rag แล้วมันคาดเดายากขึ้นอะไรเงี้ย Testing ก็จะยากยิ่งขึ้นนะ อันนี้ก็คือจะเป็นข้อสรุปแล้วกันนะครับว่าตัว Vanilla Rag กับตัว Agentic Rag เนี่ยมันมีข้อแตกต่างกันอย่างไรบ้าง ก็หวังว่าทุกคนจะชอบคลิปนี้ แล้วถ้าอยากให้ทำคลิปแบบไหนอีกก็บอกได้ในคอมเมนต์
